# STAGE — 点对点拉力赛

一个纯前端的单人计时拉力赛。无对手车、无开场秀、无联网，你唯一要打败的是时间。
双击 `index.html` 即可开跑：不需要构建、不需要服务器、没有 npm 依赖、没有 CDN，
所有地形/几何/贴图/音效/赛道/路书都是运行时程序化生成的。

```
index.html          ← 双击这个
css/style.css
js/core/mathx.js    数学 / 四元数 / 矩阵 / 噪声 / PRNG
js/track/track.js   赛段生成：曲率语法、海拔、路面、道具、碰撞体、路书
js/track/stages.js  6 条赛段配方
js/physics/tire.js  轮胎联合滑移曲线
js/physics/vehicle.js  6DOF 刚体 + 四轮悬挂 + 传动/离合/换挡/损伤
js/render/*         WebGL 管线、程序化网格、粒子、座舱
js/input/input.js   键盘渐进 / 手柄线性 / 触屏
js/audio/audio.js   程序化引擎与轮胎音、领航员语音
js/ui/*             HUD 与菜单
js/game.js          固定步长循环、镜头、计时、幽灵、损伤
js/main.js          启动
```

物理与渲染完全分离：物理固定 **240 Hz** 推进（`FIXED = 1/240`），渲染按帧插值；掉帧时只会少画几帧，
物理轨迹保持一致（用 1/240 与「抖动帧时间 + 固定步长累加」两种方式跑 3 秒，位置差 < 1 cm）。

## 操作

| 功能 | 键盘 | 手柄 | 触屏 |
|---|---|---|---|
| 油门 | W / ↑ | RT（线性） | 右下「油门」 |
| 刹车 | S / ↓ | LT（线性） | 右下「刹车」 |
| 转向 | A / D / ← → | 左摇杆 | 左下 ◀ ▶ |
| 手刹 | 空格 | A | HB |
| 升挡 / 降挡 | E / Q | RB / LB | ＋ / － |
| 离合 | 左 Shift | X | — |
| 起动机（熄火后） | K | B | — |
| 视角（座舱/车头/追尾） | C | Y | — |
| 暂停 | Esc / P | Start | — |
| 重开本赛段 | R | — | — |

键盘的油门/刹车/转向都是**渐进模拟输入**：轻点给一点，长按才到底；转向速率随车速变化
（高速时同样的按键时间打出的角度更小）。手柄走原生线性轴，摇杆死区、输入线性度、
油门/刹车曲线都可以在「设置」里调。

**离合**：默认手动。起步要半联动——按住 Shift 切断动力、给油、慢慢松开。
低速拖挡会熄火（按 K 或「踩离合 + 给油」重新点火）。为避免无意义挫败，静止且踩刹车时
会自动分离离合（相当于驾驶员自己踩了离合），这是唯一一处"替玩家做动作"的地方，
不是隐藏稳定系统。

## 赛段

| # | 赛段 | 路面 | 天气 | 时段 | 长度 | 特点 |
|---|---|---|---|---|---|---|
| 1 | 铁砧岭 KETTLE RIDGE | 砂石 | 晴 | 白天 | 6.1 km | 高速砾石、长跳坡、右侧无护栏山脊 |
| 2 | 石桥村 STONEBRIDGE | 砂石 / 柏油 | 晴 | 黄昏 | 5.4 km | 村道窄巷、石墙贴边、柏油与砾石反复切换 |
| 3 | 松针夜路 PINE NEEDLE | 砂石 | 雾 | 夜间 | 6.4 km | 车灯是唯一光源，树墙紧贴路面 |
| 4 | 冰川隘口 GLACIER PASS | 雪地 | 雪 | 白天 | 6.6 km | 雪墙、深沟、冰面斑块，刹车距离翻倍 |
| 5 | 雨谷 RAIN VALLEY | 柏油（湿） | 雨 | 白天 | 5.8 km | 积水成片，湿柏油峰值高但很窄 |
| 6 | 雾凇林 HOARFROST | 雪泥 / 砾石 | 雾 | 黎明 | 6.0 km | 半融雪泥盖住砾石，抓地在两种路面间跳 |

每条赛段都由「曲率语法」程序化拼出来：发夹、盲弯、连续 S、收紧/变宽、跳坡、
窄桥、林道、村庄窄巷、山脊悬崖。宽度在 2.0–3.5 m（半宽）之间变化，
窄处会真的让人紧张。1/3 与 2/3 处各有一个分段时间点。

路面差异不只是贴图：

| | 峰值附着 | 峰值滑移角 | 峰值后衰减 | 制动（100→0） |
|---|---|---|---|---|
| 砂石 | ≈0.72 | 9.7° | 缓（掉到 73%） | ≈73 m |
| 柏油（干） | ≈1.05 | 8.0° | 较快（掉到 62%） | ≈50 m |
| 雪地 | ≈0.38 | 12.6° | 很缓（掉到 78%） | ≈90 m |

另外还有：柏油被砂石带脏后抓地下降（脏路）、车辙与脏污随行驶累积并写入本地存档、
积水/冰面抓地骤降但有可恢复的过渡区。

## 调校

调校会真实改变车辆性格，不是数值装饰。

| 参数 | 影响 |
|---|---|
| 终传比 | 大→加速猛极速低；小→相反 |
| 前/后弹簧硬度 | 硬→响应快、极限更突然；后弹簧偏硬会让车尾更活 |
| 前/后悬挂行程 | 长→落地更稳；短→频繁触底，落地会顶到缓冲块 |
| 前/后回弹阻尼 | 回弹太慢 → 连续颠簸里车身累积摇摆 |
| 前/后防倾杆 | 前杆硬→推头；后杆硬→甩尾。这是最直接的平衡工具 |
| 中央差速（前） | 0 = 纯后驱（给油就甩），1 = 纯前驱（推头），0.42 = 四驱 |
| 中央耦合锁止 | 越大越接近锁死，四轮互相拖拽，转向迟钝但稳 |
| 前/后桥限滑 | 大→两轮同步，甩尾可控；小→内侧轮空转 |
| 刹车前后比 | 偏前稳定；偏后入弯更灵，也更容易锁后轮打转 |
| 刹车力矩 | 总制动力 |
| 胎压 | 过高过低都掉抓地（1.6–3.0 bar） |
| 轮胎类型 | 砂石胎全能；干地柏油胎铺装路抓地高、砂石上很差；雪胎只在雪地有效 |
| 转向锁角 | 大角度更容易救车，也更容易打过头 |
| 前/后车身高度 | 影响重心与触底概率 |

调校按赛段保存在 localStorage（「保存此调校」）。

把一台推头的车改成甩尾车，最有效的三招：后防倾杆加硬、前防倾杆放软、
中央差速往后偏（0.42 → 0.2）。

## 驾驶技巧

1. **刹车是为了转向。** 入弯前把速度降到能"用方向"的程度，重刹时前轮已经用掉大部分
   附着，这时打方向只会推头。刹-放-转-给油，四拍分开。
2. **用重心开车，不是用方向。** 收油会让重心前压、后轴变轻，这是最快的入弯方式；
   出弯给油重心后坐，后轴压地才有牵引。四驱车在弯中给油会让车头往外推，收油会收窄线路。
3. **反打要早、要少。** 车尾开始滑的时候（车头指向弯心内侧），方向要往回带一点点，
   同时收油。等车身已经横过来再打就晚了——但本作的轮胎峰值后只掉到 73%，还有救。
4. **听转速换挡。** 涡轮在 3000 rpm 以后才真正推力，出弯前把转速维持在 3500 以上；
   降挡有转速保护（超过 7350 rpm 会拒绝），但锁着轮子降挡会骗过保护，别这么干。
5. **雪地提前两倍刹车。** 雪地峰值附着只有砂石的 55%，而且峰值滑移角更大——方向要"喂"进去。
6. **窄桥别犹豫。** 桥面只有 3.9 m 宽，两侧是石栏。上桥前把车摆正，匀速过。
7. **柏油怕脏。** 从砂石切到柏油的头几十米，轮胎上带着砂石，抓地会明显下降，
   这几秒最容易出事。
8. **看路书，不要只看路。** 领航员的提前量默认 2.4 秒（可调 1.0–4.0 s），
   报"左四收紧"时你应该已经在准备刹车了。

## 损伤与维修

分 13 个部位独立记账：发动机（功率衰减 + 失火）、变速箱（高负载下脱挡、换挡变慢）、
转向（跑偏 + 锁角变小）、四个悬挂（弹簧变软 + 车身塌陷）、四条轮胎（抓地下降）、
灯光（夜间视野）、车身。

每个部位的状态都会实时反映到手感、声音和 HUD 的损伤图上，而不是一个总进度条。
赛事模式（6 赛段连跑）之间进维修区，维修总预算 300 秒，修哪一块要做取舍。

## 计时与幽灵

- 实时计时 + 两个分段点，结算页给出分段成绩与失误清单（冲出赛道/撞树/撞护栏/
  熄火/打转/脱挡），并按赛道距离标注位置。
- 个人最佳成绩与最佳幽灵车存在 localStorage；幽灵车按 10 Hz 记录，
  重跑同一赛段时以半透明蓝色车影对比。
- 冲出赛道超过 0.6 秒记一次失误，超过 1.2 秒加罚 2 秒。

## 音频

全部用 WebAudio 程序化合成，没有任何外部音频文件：

- 引擎：三路振荡器（基频 = 转速/30）+ 带通噪声，低通截止随转速与油门变化，
  靠听就能判断换挡点；收油有回火放炮，松油门带涡轮泄压声。
- 涡轮：正弦啸叫，频率与音量随增压值变化。
- 轮胎：带通噪声，增益由滑移量驱动，柏油上更尖。
- 路面噪声、风噪、砂石敲底盘、换挡机械声、起动机。
- 领航员：`speechSynthesis`（zh-CN）。系统没有中文语音包时静默，屏幕路书仍然工作。

## 做了哪些简化（重要）

为了在浏览器里跑满 60 帧，以下地方是刻意的近似，不是"没做完"：

1. **轮胎是稳态曲线，不是热力学模型。** 没有胎温、胎压随温度变化、磨损随里程累积
   （胎压是可调参数但不是动态状态）。联合滑移用归一化滑移向量 + 形状函数近似
   Pacejka，峰值后平缓下降。
2. **悬挂是射线悬挂（raycast），不是多体。** 簧下质量被忽略，轮胎垂向刚度并入弹簧；
   车身只有一个刚体，没有柔性。
3. **发动机是一维查表 + 涡轮一阶滞后。** 没有进排气波动、没有爆震、没有增压器惯量细节。
4. **离合与传动用"单步不越过零滑差"的容量限制近似**，避免 240 Hz 下的数值颤振；
   静止踩刹车会自动分离离合。
5. **碰撞体是圆/长方体**（树、石、护栏、房屋），不是三角网格碰撞。
   车身用三个圆近似，没有真正的钣金变形，只有分区损伤数值。
6. **地形是沿中心线放样的带状网格**（每侧外扩到 90 m + 远景丘陵噪声），
   不是无缝开放世界；超出 ~30 m 有软边界把你推回来。
7. **车辙/脏污按赛段节点累积并持久化**，但只影响高度与颜色，不是流体。
8. **水面是"抓地力骤降 + 水花粒子"**，没有真正的流体动力学与水膜排量。
9. **倒车、坡起、拖挡等都有建模，但没有做离合器磨损与变速箱油温。**
10. **幽灵车只是位置回放**，不记录车轮转角与悬挂状态。

## 技术说明

- **零构建**：所有脚本用传统 `<script>` 加载（不是 ES module），因此 `file://`
  下双击可用——浏览器会因 CORS 拒绝 `file://` 的模块导入，这是刻意的取舍。
  模块之间通过 `window.RG` 命名空间挂载，物理层不知道渲染层的存在。
- **WebGL 1.0**，手写着色器；一个主程序（顶点色 + 半球环境光 + 平行光 +
  双聚光头灯 + 指数雾 + 程序化颗粒噪声），一个天空程序，一个粒子程序，
  一个纹理程序（后视镜 RTT 与仪表盘画布）。
- **地形分块**：每 96 m 一个 chunk，包含路面、路肩、远景带与全部道具（烘焙进同一
  个顶点缓冲），按视锥 + 距离剔除。整车一条赛段约 20 万三角形，视野内通常 3–8 万。
- **固定步长**：物理 240 Hz，最多每帧追 12 步；渲染用上一帧与当前帧插值
  （位置线性、姿态 slerp），所以 30 fps 下画面依然平滑，且手感与 60 fps 完全一致。
- **存档**：`localStorage` 一个键（`rally_time_v1`），含最佳成绩、分段、幽灵、调校、
  路面磨损。清空浏览器数据即重置。
- **演示模式**：`index.html?auto=1`（可加 `&stage=kettle&cam=0`）会让车沿中心线自动
  驾驶并跳过倒计时，用来快速看画面或验证物理；正常打开不受影响。

## 已知边界

- 软件渲染（无 GPU）下帧率会很低；需要支持 WebGL 的浏览器。
- 语音播报依赖系统 TTS 中文语音包；没有时只有屏幕路书。
- 手柄需要在页面加载后按一下任意键，浏览器才会把设备暴露给 `navigator.getGamepads()`。
- 手机端帧率取决于 GPU，中低端机型建议在「设置 → 画质」里选「中」。
