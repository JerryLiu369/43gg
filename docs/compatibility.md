# 长期兼容约定

43gg 已经有真实玩家：别人收藏过的链接、浏览器里存着的进度，都依赖下面几条约定。新增游戏、重构代码、AI Studio 会话或任何外部 Agent 改动时，都不能破坏它们。确实需要变更时，先在 PR 或提交说明里写清迁移方案。

## 应用 id 只增不删

- `src/apps/registry.ts` 中每个游戏的 `id`（如 `ink-blade`）同时是对外链接 `?app=<id>`、存档键名和大厅进度读取的依据。
- 已发布的 `id` **不改名、不删除、不复用**。游戏下线时，在注册表中保留条目并另行处理展示，而不是让旧链接失效。
- `src/shell/shell.test.ts` 中的 `PUBLISHED_IDS` 记录了已发布的 id。新游戏上线后，把它的 id 追加进去。

## 路由与部署路径

- 规范链接格式是 `?app=<id>`；`#/apps/<id>`、`#/app/<id>`、`#<id>` 作为兼容入口长期保留。
- `vite.config.ts` 固定 `base: './'`，所有跳转都通过 `src/shell/router.ts` 生成。这样构建产物放在任何路径下都能运行：本地根路径 `/`、GitHub Pages 的 `/<仓库名>/`，以及仓库将来改名后的新路径。
- 不在源码中写死部署路径或站点域名。
- GitHub Pages 地址跟随仓库名。仓库改名后，旧的 Pages 链接不会自动跳转，需要同步更新 README 顶部链接。

## 本地存档键名

存档放在浏览器 `localStorage` 中，按站点域名（`jerryliu369.github.io`）共享，与部署路径无关。改键名等于清空所有玩家的进度。

- **统一格式**：`43gg.<id 下划线形式>.<用途>.v<版本>`，例如 `43gg.ink_blade.meta.v1`、`43gg.chrono_stage.records.v1`；大厅自身使用 `43gg.hub.*`。新游戏照此命名。
- **前缀 `43gg.` 冻结**：仓库公开时统一为该格式，此后任何品牌或仓库改名都不改存档键名。
- 存档结构不兼容时，升级末尾的版本号（`.v1` → `.v2`），并在 `storage.ts` 里读取旧版本并迁移。读到损坏或未知的数据时，安全回退到初始状态，不能白屏。
- `src/shell/hubProgress.ts` 会读取各游戏的存档来显示大厅进度。修改存档结构时，记得同步修改它。

## 注册表结构

- `WorkspaceAppEntry` 不删除或重命名已有字段，避免还没合入的游戏分支冲突。新增字段优先设为可选；必须设为必填时（如 `author`、`model`），在同一次提交里为所有已有条目补齐。
- 分类（`AppCategory`）可以新增，不删除已有分类。

## 构建与发布

- 推送 `main` 后，GitHub Actions 运行 `npm run apps:check`，通过后才发布 `dist/`。PR 会跑同一套检查。
- 单元测试通过 `src/**/*.test.ts` 自动发现，新游戏的测试文件放在自己的目录里即可，不需要修改测试清单。
- 仓库是公开的：密钥只放在本地未跟踪的 `.env` 或服务端环境变量里，永远不要提交。
